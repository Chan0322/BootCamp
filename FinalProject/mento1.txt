# 논의 항목

- 데이터 어떻게 넣을 지
- 기능 줄이기
- 사용자가 mbti
- 판매자가 상품 등록할 때 아무 상품이
- 카카오톡이 없으면 불가능
- 수신자의 카카오 아이디가 필요함
- 카카오에 있는 사람들에게 보내는게 타겟
- 카카오톡이 장애가 생겼을 때 임팩트있는 체인지가 있으면 독립적으로 우리 사이트가 운영이 불가능.
- 4개 구매하고 한개 환불했을 경우, 1개만 취소했을 경우
- 결제만으로도 고려할 게 많음
- 사용자가 누르지 않고 타임아웃 하게 되면 끊어야됨. 내부적으로 스케줄만들어서.
- 판매자는 없애고 상품 그냥 다 만들어놓고 (판매자는 개발 후 따로 진행)
⇒ 관리자의 역할도 간소화됨. (입점 승인 / 거부 등)
- 발표할 때 화면만 만들어놓기
- 내일 할 건 db 공용으로 설치하고 환경 도구 맞추고 버전 정확히 맞추고 캄반? 9시 5분되면 오늘 내가 해야될 것. 5시에 오늘 내가 하려고 했는데 못한것. 내가 어디까지 햇고 내일 뭐할 건지 다 작성할것
- 상품은 db에 그냥 넣어놓고 입점
- 결제 장바구니 결제 중간 취소했을 때 트랜잭션 잘 처리되는지가 취업할 때 중요. 카카오톡에 선물안받았을  때 어떻게 할 건지(읽씹, 안읽씹 할 때) 예외 사항을 구현하는게 더 임팩트 있을 것.
- 판매자 관리자는 보여지는 메뉴만 만들고 기능 구현 x
- ai 챗봇도 빼는게 나을듯.(종료 후 구현)
- 발표할 때는 api 키, 시크릿 키만 받아놓고, 챗봇
- 영어, 중국어든 마찬가지라고 하고 이거에 대한 내용은 답변하지마라고 프롬프트 넘기자.
- 수신자한테 카톡으로 테스트 넘겨서 수신자가 직접 테스트하게끔 해서 그 mbti로선물하는 식
- mbti 이미지로만 간단하게 테스트하는 방식도 있음
- 내 mbti가 중요하지 않음.
- 어떻게 하면 재미있게 상대의 mbti을 알아내고, 선물했을 때 결제했을 때 실패시 중간 실패 시 어떻게 처리할 건지가 취업에 더 도움됨.
- 카테고리별로 데이터 상품 다 넣고
- 예외처리 부분에 집중할 것
- 카카오톡 없는 사람한테 sns로 보내자(기간 남을때)(인스타, sms 등)
- 두번 연속 눌렀을 때 중복처리 어떻게 할 것 인지
- api 끌어올 때 친구 생일 목록 가져와서 구글 api에 연동.
- 캘린더 목록에 자동화할 수 있는 기능이 좋음
- 결제하는 도중에 재고가 0이 될 때 어떻게 처리할 건지
- 이 때 ai를 이용해서 이 상품과 유사하고 가격이 비슷한 상품을 추천해달라고 한다.
- 의류는 제외(골프, 게임기, 전자제품 이런건 필수다…..)
- 사용자 결제 수신자
- 환불, 부분취소 등 결제 관련 기능이 중요함.
- 읽씹 안읽씹 처리, 재고, 카카오톡 가는거, 데이터 db저장, 동시성 처리 (동시에 2명이 상품을 눌렀을 때 늦게 누른 사람은 어떻게 되는지 이런걸 연구해볼것)
- 카카오가 장애가 일어났을 때 버튼을 누르면 우리쪽에서 redis 설치해놨다가 que에 담아놨다가 장애가 풀리면 보내는 방식 → 헬스 체크?
- 카카오를 활용한 지인 관리. 카카오 id한번만 입력하면 일정, 친구 생일 자동화하고 친구의 mbti로 선물 상품을 추천받을 수 있어요!
- 캘린더에 집들이, 돌잔치 등록될 때 기저귀가 추천 아이템으로 나감
